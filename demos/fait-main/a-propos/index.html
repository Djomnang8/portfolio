Ce qu'est ce carnet

Fait Main raconte comment les logiciels sont réellement fabriqués : les défauts trouvés trop tard, les mesures qui contredisent l'intuition, les décisions prises sans information complète.

Chaque article part d'un projet que j'ai construit, et se termine par quelque chose que vous pouvez vérifier vous-même — une formule, un script, un protocole de mesure. Jamais par une opinion seule.

La règle qui structure tout le reste :

Un article ne peut pas affirmer ce qu'il n'a pas mesuré.

En pratique : un chiffre cite le script qui l'a produit, une affirmation s'accompagne du test qui la contredirait si elle était fausse, et « je ne sais pas pourquoi » est une phrase publiable.

La ligne éditoriale complète est publique, y compris ce que je m'interdis de publier et l'usage que je fais de l'IA dans la rédaction.

Pourquoi ce carnet existe

Trois raisons, dans l'ordre d'importance.

Pour comprendre. Un défaut qu'on explique par écrit est un défaut qu'on a compris. Plusieurs articles ici ont trouvé leur vraie cause pendant la rédaction, pas avant — écrire oblige à une continuité que la lecture de code n'impose pas.

Pour laisser une trace utilisable. Les projets se rangent, les enseignements se perdent. Un carnet garde les seconds quand les premiers ne servent plus.

Pour le rendre. J'ai appris avec des articles écrits par des gens qui prenaient le temps d'expliquer leurs erreurs. C'est ma contribution au même stock.

Comment ce site est fait

Sans dépendance. Aucun npm install, aucun node_modules, aucune bibliothèque tierce.

  • Les articles sont des fichiers Markdown avec un en-tête de métadonnées.
  • Un analyseur Markdown maison, couvert par 34 tests, produit le HTML.
  • Toutes les couleurs viennent d'un fichier tokens.json unique ; le CSS en est généré, et un script vérifie les 32 paires de contraste à chaque intégration.
  • Quatre vérifications tournent en intégration continue et bloquent la publication en cas d'échec : contraste, conformité éditoriale, métadonnées SEO, liens internes.

Le tout est dans un dépôt public, y compris les scripts de vérification et le rapport éditorial généré à chaque publication.
